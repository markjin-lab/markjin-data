## 统一系统观解读

统一系统观是什么，见[关于页](/about/)。本期三篇论文都可在 arXiv 阅读；第 1 条的 arXiv 条目注明 Accepted at NeurIPS 2026（poster），第 2、3 条的 arXiv 条目未注明发表或评审情况 [1]、[2]、[3]。

**第 1 条：工具调用智能体碰上真实协议故障，更大模型就能更扛吗。**

背景：语言模型智能体越来越依赖经 Model Context Protocol（MCP）暴露的外部工具，但现有基准常假定工具正确且及时响应，未测真实故障下的韧性 [1]。（本站补充的通用解释：MCP 一般指让智能体按统一协议调用外部工具的一种接口约定；智能体在此一般指会调用工具并跨回合保持状态的一类语言模型系统。）

Antonio Ken Iannillo、Joshua Segun Owotogbe、Roberto Natella、Francesco Avallone、Kristina Kudryavtseva 与 Indika Kumara 六位作者于 2026-10-23 在 arXiv 公开论文《Tool-Calling LLM Agents Under Realistic MCP Faults: Scale Does Not Purchase Fault Tolerance》，并注明已被 NeurIPS 2026 接收为海报 [1]。他们提出 MCP-Injector：可插入工具调用路径的协议感知故障注入中间件，故障模型按公开 MCP 生态观测到的事件分布校准，数据来自 1,774 个开源 MCP 仓库中的 57,240 条 issue 与 pull request 讨论 [1]。

为什么重要：在交叉两种骨干规模（20B、120B）、三种智能体栈与三种故障注入条件的 1,350 格实验中，按该永久故障偏重画像抽取的故障使任务完成分从 10 分制的 8.08 降到 3.23（约降 60%）[1]。对所测两个 gpt-oss 骨干，规模并未换来更高故障耐受：120B 在故障下并未保留更大比例的无故障分数（韧性比模型，p = 0.96）[1]。不同智能体栈吸收故障的能力不同，作者认为框架层错误处理比单纯加大模型更关键 [1]。

卡在哪：摘要给出的是该故障画像下的总体降幅、两个 gpt-oss 骨干的韧性比较，以及栈间差异的定性结论，未写明各智能体栈的分项完成分，也未给出其它协议或其它骨干家族上的对应数字 [1]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在其它工具协议故障分布或其它骨干与智能体栈设定下，更大骨干是否仍未保留更高比例的无故障任务完成分，或框架层错误处理是否仍比单纯加大模型更能解释故障吸收差异。

**第 2 条：长视频里的细粒度时空记忆，现成大模型扛得住吗。**

背景：人能处理跨小时到数年的多模态流并形成支持长程推理的细粒度时空记忆，而既有基准多偏短、中等上下文，多数基础模型难以在长时程上保住细粒度信息 [2]。（本站补充的通用解释：时空记忆在此一般指同时保留「在什么地方、什么时候发生了什么」的持久表征，供后续问答与预测使用。）

Yanhao Jia 等 10 位作者于 2026-10-23 在 arXiv 公开论文《4DMemory: Benchmarking Long-Horizon Spatiotemporal Memory with Harness-Augmented Agents》，提出 LongVideo 数据集与 4DMemoryBench [2]。LongVideo 约含 900 小时视频与 5,000 余道经人工审阅的问题，覆盖视觉、文本与时空推理及多种上下文长度 [2]。作者还开发 4DMemory Harness，整合四类互补技能、22 个以上专用工具模型，以及面向具体模型的检索增强生成系统 [2]。（本站补充的通用解释：Harness 在此一般指包在模型外、负责调度工具与检索等步骤的执行框架。）

为什么重要：评估 13 个领先模型后，作者发现单独使用的基础模型在长时程任务上吃力，而 4DMemory Harness 使它们相对单独使用都提升逾 50% [2]。相对既有基准，同一批模型在 4DMemoryBench 上的表现下降逾 10% [2]。

卡在哪：摘要给出的是相对单独使用逾 50% 的提升，以及相对既有基准逾 10% 的下降，未写明各模型的绝对分数，也未给出四类技能或各工具模型的分项贡献 [2]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在其它长视频语料或其它工具编排设定下，单独基础模型是否仍明显弱于带 Harness 的组合，以及相对短上下文基准的落差是否仍常见。

**第 3 条：智能体 Harness 反复推理，能不能少花 token 又保住成功率。**

背景：智能体 Harness 在工具反馈之后常再次调用推理，即便更早一次调用已经确定下一步动作 [3]。

Yuhua Jiang、Chang Xu、Feifei Gao 与 Li Zhao 四位作者于 2026-10-23 在 arXiv 公开论文《HarnessMM: Recursive Self-Improvement for Harness Token Efficiency》，提出 HarnessMM（Harness Minus Minus）：用受护栏约束的决策复用与反复自我改进，改进 Harness 的 token 效率；控制器在模型—工具边界复用已解析决策，以替换后续推理回调，而行动者权重保持固定 [3]。（本站补充的通用解释：token 一般指模型读写文本时计量的基本单位，直接影响推理费用与时延。）

为什么重要：在 HumanEval 上，HarnessMM 将 Codex 成功率维持在 90.82%，同时把 Tokens/task (k) 从 66.72 降到 47.02（节省 29.54%）[3]。对 DeepSeek Harness，成功率从 71.43% 升到 85.71%，Tokens/task (k) 从 96.28 降到 11.62（节省 87.93%）[3]。作者认为，受护栏约束的决策复用，是减少既有 Harness 中重复推理的一条可行路径 [3]。

{{< industry-link item="3" industry="ai" side="cost" inference="Tokens/task 下降是否对应这类智能体 Harness 的推理成本下降" >}}来源报告的是在维持或提高成功率的同时降低 Tokens/task 的 Harness 改法 [3]，对应这个产业里智能体编排一类推理成本。{{< /industry-link >}}

卡在哪：摘要给出的是 HumanEval 与 DeepSeek Harness 两组成功率与 Tokens/task 数字；另有独立的 MBPP 消融报告成本较单次使用图下降 26.91%、较保留回调下降 19.52%，但该对照是成本口径而非 Tokens/task，也未给出美元或 GPU 时费用差 [3]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在其它编码基准或其它 Harness 设定下，受护栏约束的决策复用是否仍能在不明显牺牲成功率的前提下压低 Tokens/task。
