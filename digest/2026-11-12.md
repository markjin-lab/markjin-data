## 统一系统观解读

统一系统观是什么，见[关于页](/about/)。本期两篇论文都可在 arXiv 阅读，两个条目均未注明发表或评审情况 [1]、[2]。

**第 1 条：模型升级后，旧版本算好的 KV 缓存还能不能接着用。**

背景：摘要称，在语言模型更新之间复用 KV 缓存，可以省去对共享上下文的重复计算，但模型权重变了，这些缓存究竟保留了什么，是一个根本问题 [1]。（本站补充的通用解释：KV 缓存保存已处理 token 的键值状态，供后续生成步骤复用；首个 token 时延指从提交请求到生成第一个 token 的时间。）

Zhikun Tao、Fangyong Jin 与 Junping Zhao 三位作者于 2026-11-10 在 arXiv 公开论文《Can KV Cache Be Reused Across Model Updates? A DeepSeek-V4-Flash Case Study》，研究四次模型更新中直接复用缓存的效果，并详细考察从 DeepSeek-V4-Flash 到 Flash-0731 的更新；作者提出「功能缓存偏离度」，比较复用缓存与原生缓存下的下一 token 分布 [1]。

为什么重要：在已有源缓存的情况下，复用在三个前缀较长的问答基准上带来 2.10–5.08 倍的首个 token 时延中位提速 [1]。但检索准确率在不同更新之间差异很大，从接近原生表现到大幅下降不等 [1]。

{{< industry-link item="1" industry="ai" side="cost" inference="省去的重复计算是否对应推理服务实际算力开支的下降" >}}来源报告的是复用缓存带来的首个 token 时延中位提速倍数 [1]，对应这个产业里长上下文推理服务一类的计算成本。{{< /industry-link >}}

卡在哪：摘要写明，即使生成的第一个 token 一致，也不能保证回答内容或停止行为一致；在单 token 检索任务中，兼容性随前缀变长而下降 [1]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在别的模型系列的版本更新上，直接复用 KV 缓存时，能否同样取得数倍的首 token 提速，同时把检索准确率的损失控制在小幅范围内。

**第 2 条：混合架构模型里压缩历史信息的循环状态，能不能再压一压，好让解码更快。**

背景：摘要称，混合模型把 softmax 注意力与线性注意力结合起来，后者把历史压缩成固定大小的循环状态，以平衡模型质量与推理效率 [2]。作者发现，线性层的查询、键和值集中在一个稳定的低维子空间里，他们称之为「线性注意力汇」，因此每个状态实际上是低秩的；但现有服务系统仍以稠密形式保存这些状态，每个解码步都整体读写，显存流量随批大小增长并主导解码成本 [2]。（本站补充的通用解释：低秩指一个矩阵可以用少得多的数据近似表示。）

Haolin Jiang、Weihang Li、Zhongzhu Zhou、Jinwen Pan、Santosh Pandey 与 Hang Liu 六位作者于 2026-11-10 在 arXiv 公开论文《SinkState: On-the-Fly SVD of Recurrent States for Efficient Hybrid LLM Serving》，提出 SinkState：在整个推理过程中以自适应低秩形式存储每个循环状态，配合缓冲更新和只限于主子空间的局部 SVD，并在 CPU 上异步合并其余分量 [2]。

为什么重要：在四个含 Mamba-2 与 Gated DeltaNet（GDN）层、参数从 4B 到 120B 的混合模型上，与 Mamba-SSM 和 FLA 相比，SinkState 把循环状态的峰值显存最多降低 2.6 倍（平均 1.9 倍），解码最多提速 1.58 倍（平均 1.25 倍），同时保持准确率 [2]。

{{< industry-link item="2" industry="ai" side="cost" inference="更低的显存占用与更快的解码是否对应推理服务实际成本的下降" >}}来源报告的是相对 Mamba-SSM 与 FLA 的循环状态峰值显存降幅与解码提速倍数 [2]，对应这个产业里混合模型推理服务一类的显存成本。{{< /industry-link >}}

卡在哪：结果只针对含 Mamba-2 与 GDN 层的混合模型；摘要给出的是相对两种现有系统的倍数，没有写明完整的准确率对比 [2]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在别的线性注意力或混合架构上，是否也观察到循环状态的低秩结构，并据此取得约两倍量级的显存降幅和两成以上的解码提速。
