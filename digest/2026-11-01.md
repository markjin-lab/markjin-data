## 统一系统观解读

统一系统观是什么，见[关于页](/about/)。本期三篇论文都可在 arXiv 阅读；第 1 条的 arXiv 条目注明 Accepted at COLM 2026，第 2、3 条未注明发表或评审情况 [1]、[2]、[3]。

**第 1 条：长程智能体，能不能自己整理工作记忆，在少很多输入 token 的情况下仍把难任务做完。**

背景：由大语言模型驱动的智能体在长程任务上常因工作记忆被不断膨胀、无关信息冲淡而认知过载，规划与推理随之变差；需要一种能主动整理上下文的办法 [1]。（本站补充的通用解释：工作记忆一般指智能体在一步步解题时临时保留的任务状态与中间事实；上下文一般指模型一次推理时可见的全部提示文本。）

Zheng Zhu、Xiaozhuan Liang、Xi Chen、Bei Yu 与 Jiaya Jia 五位作者于 2026-10-29 在 arXiv 公开论文《Don't Lose the Thread: Empowering Long-Horizon LLM Agents with Cognitive Resource Self-Allocation》（已被 COLM 2026 接收），提出认知资源自分配（CORAL）：把可调用的工作记忆管理工具交给智能体，让它为任务进度与已核验事实做检查点，并在重置杂乱上下文后只保留检查点信息、开启新一轮解题 [1]。

为什么重要：在 GAIA 基准上，CORAL 配合 8B 模型达到 42.8% 平均准确率，并在最具挑战的长程任务（Level 2 与 Level 3）上增益尤为明显 [1]。这些增益伴随显著更低的推理成本：CORAL 消耗的输入 token 比 ReAct 智能体少 6–7 倍 [1]。它还泛化到多跳知识问答，并在更难的 BrowseComp 上把一个强专有智能体再提高 8.0 分 [1]。

卡在哪：摘要给出的是 GAIA 平均准确率、输入 token 倍数与 BrowseComp 分差，未写明完整分项表，也未给出美元或 GPU 时费用差 [1]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在其它长程设定或其它模型规模上，让智能体用检查点式工作记忆自分配重置上下文，是否仍能在保住或提高难任务准确率的同时，把输入 token 压到约 ReAct 的 1/6 到 1/7。

**第 2 条：为省成本把多条样本塞进同一提示，判定会不会跟着批次一起变。**

背景：实务上常为省成本，让语言模型在同一提示里给许多彼此独立的样本打分，并默认各条判定可分、不依赖同批其它样本或其位置 [2]。（本站补充的通用解释：批内打分一般指把多条待评样本放进同一次提示、由模型一并给出判定；可分一般指单条判定不因同批其它条目或其顺序而改变。）

Peng Xie 与 Amr Alanwar 两位作者于 2026-10-29 在 arXiv 公开论文《Judged in Company: In-Context Batching Makes LLM Verdicts Depend on Other Items》，在三类判定任务与五款 4–9B 开源权重模型上，检验把同一批 2,000 条样本随机分成每批 25 条时判定是否仍稳定 [2]。

为什么重要：同一批 2,000 条被分到不同随机批次时，伤害与短答评分上有 11–22% 的判定改变，比改条目键名或改写指令还多 6.5–13.3 个百分点；相对人类标签的 AUROC 与单条打分仅差 −0.033 到 +0.010 [2]。在 14–32B 的四款模型上，仍有 6–15% 的判定改变 [2]。即便对十五个随机批次取多数票，仍有 8.4–17.8% 的判定与单条打分不一致 [2]。作者建议对含糊样本逐条打分，并用缓存前缀收回大部分成本 [2]。

卡在哪：摘要给出的是翻判比例、AUROC 差与多数票残留翻判，未写明完整分项表，也未给出美元费用差 [2]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在其它判定任务或其它模型族上，把多条独立样本塞进同一提示时，翻判比例是否仍显著高于改键名或改指令的扰动，且多数票仍难对齐单条打分。

**第 3 条：推测解码省下的能量，会不会在大批量或低接受率时变成额外能耗。**

背景：大语言模型服务受机房电力约束；每 token 能耗决定能服务多少 token，时延目标则约束用户多久拿到输出。推测解码用起草模型提出后续 token，由目标模型在一次前向里验证，但每个起草 token 无论是否接受都要验证，省下的能量取决于接受了多少 [3]。（本站补充的通用解释：推测解码一般指先由较小模型起草若干后续 token、再由目标模型一次性核验接受或回退的一类加速解码；接受率一般指起草 token 中被目标模型采纳的比例。）

Bole Ma、Ayesha Afzal、Jan Eitzinger、Harald Koestler 与 Gerhard Wellein 五位作者于 2026-10-29 在 arXiv 公开论文《Only Accepted Tokens Count: An Energy Accounting of Speculative Decoding Under Latency Targets》，在启用 CUDA graphs 的 SGLang 生产服务条件下，于 H100 与 H200 GPU、批量至 64、跨 5 个语料测量推测解码能耗 [3]。

为什么重要：在稠密模型上，能耗主要由验证而非起草主导；节省随批量增大而缩小，因为批处理已摊薄了推测本想在接受 token 间分摊的权重读取 [3]。大批量时，分块起草可能把验证推过算术与访存平衡点进入算力受限区，节省变成损失，低接受率起草还会抬高每 token 能耗 [3]。用推测去满足更紧的时延目标会额外耗能；更大批量在无推测时已能降低每 token 能耗，推测只在接受率高时才叠加节省 [3]。

卡在哪：摘要给出的是验证主导、批量与接受率如何改变节省的方向性结论，未写明单一百分比总表，也未给出美元电费差 [3]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：其他团队在其它目标模型族或其它起草方案上，于生产服务条件测量时，是否仍看到大批量或低接受率把推测的能耗节省压成损失。
