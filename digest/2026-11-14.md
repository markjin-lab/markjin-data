## 统一系统观解读

统一系统观是什么，见[关于页](/about/)。本期解读的论文于 2026-11-12（UTC）提交 arXiv；CapLite 条目未注明同行评审结论；AgentSSL 条目及 PDF 首页标注 NeurIPS 2026，本站未另核官方接收名单。以下研究结果按作者报告表述，本站没有复现实验 [1]、[2]。

**第 1 条：小模型写出的安全策略可能出错时，能否让代码直接核对它究竟有权做什么。**

背景：这项研究比较几种用于抵御提示注入的执行约束。部分方案先让智能体模型生成程序、权限策略或工具依赖图，再由代码执行这些材料；作者在被测模型上发现，材料写错后，约束可能放过攻击，也可能让正常任务无法运行 [1]。（本站补充的通用解释：提示注入是把指令藏进邮件、网页等数据，试图改变智能体的行为；写操作是发送消息、修改对象、转账等会改变外部状态的动作。）

Zimo Xu、Wenzhuo Liu 与 Hideki Nakayama 于 2026-11-12（UTC）提交论文《CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts》。CapLite 先让规划器只看用户请求与工具说明，固定计划中的写操作；代码根据工具名称、说明和参数结构判断权限，执行前再核对收件人、金额、对象或目的地等参数值是否由用户请求明确给出或经用户确认。后续工具返回的文字不能追加新的写操作；缺少授权参数时，它会要求确认 [1]。

为什么重要：主攻击方案是 AgentDojo 的 important_instructions。15 个开放权重模型各运行 929 个攻击目标需要工具调用的回合，CapLite 的成功攻击数为 0/13,935。论文另测任务可用性：受攻击任务成功率按每模型 949 个攻击配对统计，跨 15 个模型平均为 29.0%，CaMeL 为 27.2%，未防御智能体为 50.2% [1]。（本站补充的通用解释：开放权重指公开发布模型参数；任务成功率衡量用户任务是否完成，攻击成功率衡量攻击者目标是否达成，两者不是一项指标。）

每回合平均 token 用量，CapLite 为 1.71 万、CaMeL 为 9.37 万。这里统计提示词与输出 token，并合并每模型的 97 个无攻击任务和 949 个受攻击回合；它不是只统计攻击回合，也不是按货币计价的实付成本 [1]。（本站补充的通用解释：token 是模型处理文本时使用的片段单位。）

{{< industry-link item="1" industry="ai" side="cost" inference="减少模型调用的 token 用量能否降低这类智能体服务的实际推理费用" >}}上述 token 用量 [1] 对应智能体服务的模型计算投入，来源报告的技术用量不直接等于实际费用。{{< /industry-link >}}

卡在哪：这个保证信任用户请求、工具及其说明，约束的是写操作序列和收件人、金额等授权参数；消息正文等自由文本、时间值和最终回答并不受同样保护。主攻击指标排除了 20 个只要求最终回答多说一句话的配对，附录确有 CapLite 在这种攻击下重复攻击句的例子 [1]。所有结果来自 AgentDojo 的四个模拟场景，没有真实用户、账号或数据；需要用户确认的回合在实验中无人作答，计为任务失败 [1]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：不同团队在其他工具集或真实任务中使用这类请求参数约束时，能否同时报告越权执行、用户任务完成率、确认请求与总 token 用量，并把最终回答受污染的情况单独统计。

**第 2 条：智能体已经找到了好程序，在缺少可靠验证标签时，能否把它选出来。**

背景：AgentSSL 把半监督学习变成程序搜索：给智能体少量有标签样本和较多无标签样本，让它生成、执行并修改学习程序。作者将发现好程序与从候选池中选出可用程序分开评估 [2]。（本站补充的通用解释：半监督学习同时使用少量有标签数据和大量无标签数据；标签是样本对应的已知类别或答案。）

Ethan Lin、Akanksha Sarkar、Ziang Liu、Kristin Branson 与 Jennifer J. Sun 于 2026-11-12（UTC）提交论文《AgentSSL: Can MLE Agents Leverage Unlabeled Data?》。智能体通过带噪验证反馈或无监督指标迭代搜索。图像分类实验只允许与人工对照相同的 CLIP ViT-B-16、DINOv2-B 骨干及同一微调库，数据划分也相同；搜索时间按对应基线的计算成本分配 [2]。（本站补充的通用解释：骨干是构成模型主要特征提取部分的基础网络；微调是在已有模型上继续训练，使其适应任务。）

为什么重要：表 1 比较六个数据集、各两种每类标注样本数，共 12 个设置，并在三个随机划分上评估。若事后按测试集平均准确率选出发现池中的最佳程序，智能体结果在其中 8 个设置超过最好的人工对照。最大差值是 RETINO 每类 40 个标注样本的设置：带噪验证反馈方案找到的最佳程序准确率为 72.47%，该格最佳人工对照为监督学习的 50.66%，表中直接列出优势 21.81 个百分点 [2]。这是已知测试成绩后选出的最佳候选表现，实际选程序还需要另算。

表 2 衡量用反馈分数实际选程序时，相对该候选池中测试最优程序损失多少准确率，并跨随机种子取平均。RETINO 每类 80 个标注样本、带噪验证反馈方案的表格值为 −47.29，这里对应选中程序与池内最优之间 47.29 个百分点的准确率缺口 [2]。作者还提供 ProgramSelectBench，汇集 16,977 个预评估程序实例，其中包括人工对照与智能体方案；同一实现的不同训练划分也分别计数 [2]。

{{< industry-link item="2" industry="ai" side="cost" inference="有限标签的不同分配能否降低机器学习服务的实际数据标注费用" >}}来源研究如何在训练和程序选择之间使用有限标签 [2]，对应机器学习服务的数据标注投入；它没有据此测量实际标注账单。{{< /industry-link >}}

卡在哪：原文将可靠选程序视为未解决的瓶颈。生态检测案例中，不使用无标签数据的 AgentSL 与 AgentSSL 表现相当；BuckTales 上两种智能体波动较大，低于使用全数据的专家基线。因此不能据这份研究认定无标签数据总能带来额外收益，或真实部署已经实现降本。作者也提醒，搜索生成的程序越多，池内最优与无标签选择结果的差距可能越大 [2]。

接下来看什么：这是本站自己的观察要点，不是论文的结论：新的程序搜索系统能否同时报告事后最优成绩、真实选择方法选中的成绩与标签预算，让发现能力和实际可用结果分别可核。
