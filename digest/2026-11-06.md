## 统一系统观解读

统一系统观是什么，见[关于页](/about/)。本期三篇论文都可在 arXiv 阅读；三条 arXiv 条目均未注明发表或评审情况 [1]、[2]、[3]。

**第 1 条：计算机使用智能体要把每一帧截图压成更少的视觉 token，能不能在任务表现接近全分辨率的同时把推理成本降下来。**

背景：计算机使用智能体（CUA）近年在若干长程基准上达到超人类表现；但把每张截图编成数千视觉 token，会在长交互历史中堆成很长上下文，抬高算力与时延。摘要称多数视觉 token 对下一步动作语义无关，或在连续截图间时间冗余 [1]。（本站补充的通用解释：视觉 token 一般指把图像切成块后送进语言模型的表征单元；prefill 是生成答案前处理输入内容的阶段；推理成本这里指完成同一次推理所需的算力或时延开销。）

Pranjal Aggarwal 与 Sean Welleck 两位作者于 2026-11-04 在 arXiv 公开论文《Visual Token Routing: Learning to keep tokens that matter》，提出 Visual Token Routing（VTR）：与视觉–语言模型一起训练一个轻量时空路由器，审视当前与上一帧截图的各图像区域，决定其视觉 token 是否进入语言模型 [1]。

为什么重要：仅 2000 步训练后，VTR 在 OSWorld、CUA-World 与电子游戏动作预测上匹配全分辨率模型，并用 2.5–5.8 倍更少的视觉 token；这些节省把推理成本最高降到约 3.3 倍，并把 prefill 最高加速约 2.9 倍 [1]。相对降低图像分辨率与其它丢弃 token 基线，VTR 在 OSWorld 上最高高出 12.8 分 [1]。

**第 2 条：智能体要把越来越长的交互历史压成摘要，能不能在保住信息的同时把压缩本身变快。**

背景：大语言模型智能体用上下文压缩管理不断变长的交互历史，但用大模型总结长历史会引入可观时延；压缩因此要在信息保留与时延之间权衡。摘要称结构化摘要槽位在独立生成时仍能保留信息 [2]。（本站补充的通用解释：上下文压缩一般指把过长的交互历史改写成更短摘要，以便继续推理；槽位一般指摘要里按字段分开的信息格。）

Yulu An、Yifei Feng 与 Xiangyang Yin 三位作者于 2026-11-04 在 arXiv 公开论文《SpecCompact: Accelerating LLM Agent Context Compaction with Slot-Parallel Semantic Speculative Verification》，提出 SpecCompact：微调小草稿模型、并行生成槽位，由目标模型逐行核实并修补被拒内容，后续起草再用已更新的槽位前缀 [2]。

为什么重要：在 AppWorld 与 τ³ 基准、两个目标模型上，SpecCompact 相对 Hermes 风格摘要取得 2.04–5.63 倍压缩加速；Hermes 内用户研究中位数压缩加速为 8.68 倍 [2]。另有下游评测显示表现取舍随模型与任务而变 [2]。

**第 3 条：混合大模型还剩少量全注意力层时，能不能在不训练、不改权重的前提下把长上下文解码加快。**

背景：大语言模型的全注意力层会让每个新生成 token 比上一个更贵，拖慢长上下文任务。混合模型用线性注意力替换多数全注意力层以降成本，但在很长上下文上，剩余全注意力层仍主导解码开销。摘要提出用组合稀疏注意力加速这些剩余层：每层关注近期滑动窗、固定前缀，以及上下文中预算内最相关的 token；窗口与预算按层用多目标搜索选定 [3]。（本站补充的通用解释：混合 LLM 一般指一部分层用全注意力、一部分层用线性或其它近似注意力的模型；解码是逐步生成答案的阶段。）
