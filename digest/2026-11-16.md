## 研究线索一：提示词中哪部分信息影响了输出

**Sketching Language Models for Context Attribution（用于上下文归因的语言模型草图方法）**，Christopher Liaw、Aranyak Mehta、Grigoris Velegkas与Felix Zhou，arXiv:2611.17313v1，2026-11-12提交（UTC）[1]。

摘要提出的上下文归因问题是：移除提示词的一部分，会怎样改变语言模型的输出。它以逐一移除的归因分析和一个固定的测量函数为研究对象 [1]。（本站补充的通用解释：提示词是交给模型的输入文字；逐一移除分析是每次去掉一个部分，再观察指定的输出指标如何变化。）

本站下一步阅读的问题是：作者用什么指标定义输出变化，稳定性假设限制了哪些输入或模型，以及理论中计算调用次数的条件怎样对应实际实验。这些是待核全文的问题；本期不介绍算法的复杂度公式、误差保证或实验成绩，不把摘要中的理论主张当作已经检查过的证明，也不据此推荐实际归因工具。

摘要短引：

> We study leave-one-out (LOO) attribution
>
> 译文：我们研究逐一移除的归因分析。

## 研究线索二：模型失效告警应在什么时刻评价

**Detection Is Not Early Warning: Evaluating Token-Level Alarms on Language Model Failures（检测不等于提前预警：评估语言模型失效的逐token告警）**，Marco De Negri等，arXiv:2611.16803v1，2026-11-12提交（UTC）[2]。

摘要把生成中的监测划分为几个问题：如何评价完整回答，如何检测已经开始的失效，以及怎样衡量失效开始之前的告警；它以带有起点标注的失效为研究情境 [2]。（本站补充的通用解释：token是模型处理和生成文字时使用的片段单位；起点标注是给一段被研究的过程指定开始位置，便于比较事件的先后。）

作为后续阅读线索，本站关心告警时点如何定义、阈值怎样确定、误报如何统计，以及不同失效类型是否需要不同起点标注。当前没有核完整评测规程或实验，不报告哪一种监测器预警更早、提高多少或已经适合部署。论文题目中的区分是研究线索的名称，不替代对具体系统预警能力的验证。

摘要短引：

> an evaluation protocol for any failure with an annotated onset
>
> 译文：一种针对具有起点标注的任意失效的评测规程。

## 研究线索三：语音听写的错误应怎样分类

**Beyond Word Error Rate: A Failure Taxonomy of Streaming Dictation ASR（超越词错误率：流式语音听写的失效分类）**，Harras Mansoor、Muhammad Wisal、Hassan Bhatti与Masood Shakir，arXiv:2611.16919v1，2026-11-12提交（UTC）[3]。

摘要把研究场景放在实时音频进入系统、转写文字用于消息的听写任务，并提出对识别、输出格式、语言处理和部分自托管系统的输入音频环节进行分类考察 [3]。（本站补充的通用解释：语音识别把说话声转成文字；流式处理是音频陆续到达时就开始处理；词错误率通常汇总词的替换、删除和插入，而不是直接统计用户修改文本的动作。）

本站拟进一步核对的，是说话人和录音条件、语言选择、音频进入模型之前的处理，以及分类规则如何对应真实修改负担。这是后续阅读清单，不是认定某一产品存在某种故障。全文尚未核对，本期不复述摘要中的品牌排名、错误比例、部署设置效果或代码可用性，也不把某个测试条件扩大为所有语言和使用场景。

摘要短引：

> what matters is which mistakes the user has to fix
>
> 译文：关键在于哪些错误需要用户修正。
